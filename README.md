# My CV

Сайт-резюме на Next.js. Контент — из GraphQL-API цифровой визитки; подписи
интерфейса (заголовки секций, кнопки) — из Tolgee.

## Локальный запуск

Нужны два процесса: API отдаёт контент, сайт его рендерит.

**1. API** — в репозитории `it-solutions-test`:

```bash
docker compose up --build
```

Поднимает PostgreSQL и GraphQL на <http://localhost:3000/graphql>, применяет
миграции и заполняет базу.

**2. Сайт** — здесь:

```bash
cp .env.example .env.local   # затем впишите NEXT_PUBLIC_TOLGEE_API_KEY
npm run dev
```

<http://localhost:3001/ru> и <http://localhost:3001/en>.

Порт 3001, а не 3000, задан в `package.json`: 3000 занят API, из которого этот
сайт берёт данные.

## Откуда что берётся

| | Источник | Где править |
| --- | --- | --- |
| Имя, должность, био, опыт, навыки, проекты, сертификаты, ссылки | GraphQL API | `prisma/seed/cv-data.ts` в репозитории API |
| Заголовки секций, кнопки | Tolgee | Tolgee / `messages/*.json` |

Язык запрашивается у API аргументом `locale` — русская и английская версии
приходят из одной базы, а не из двух копий текста.

## Если правки в резюме не видны

Next кэширует `fetch` (`revalidate: 3600`). После пересева базы:

```bash
npm run db:seed     # в репозитории API
rm -rf .next && npm run dev
```

## Сборка

```bash
npm run build
```

`output: "export"` — на выходе статика в `out/`, страницы `/en` и `/ru`
генерируются на этапе сборки. Поэтому **API должен быть доступен во время
сборки**, но не в рантайме: задеплоенный сайт ни в кого не ходит.

Если сборка идёт не на этой машине, `CV_API_URL` должен указывать на
опубликованный API, а не на `localhost`.
