# My CV

Сайт-резюме на Next.js. Контент — из GraphQL-API цифровой визитки; подписи
интерфейса (заголовки секций, кнопки) — из Tolgee.

## Локальный запуск

```bash
cp .env.example .env.local   # затем впишите NEXT_PUBLIC_TOLGEE_API_KEY
npm run dev
```

<http://localhost:3001/ru> и <http://localhost:3001/en>. **API поднимать не
нужно** — сайт читает снапшот из репозитория.

Порт 3001, а не 3000, потому что 3000 занимает API, когда он запущен.

## Откуда берётся контент

`lib/cv-snapshot.ts` — сборочная копия резюме, лежит в git. Сайт собирается из
неё, поэтому деплой ни от чего не зависит: API может быть выключен, жить на
домашнем сервере или не существовать вовсе.

API — инструмент редактирования, а не зависимость. Чтобы обновить резюме:

```bash
# 1. в репозитории it-solutions-test
#    поправьте prisma/seed/cv-data.ts
docker compose up -d
npm run db:seed

# 2. здесь
npm run cv:snapshot
git add lib/cv-snapshot.ts && git commit
```

Снапшот генерируется как TypeScript, а не JSON, и типизирован как
`Record<Locale, Cv>`. Если схема API разойдётся с тем, что ожидает сайт,
сборка упадёт здесь с внятной ошибкой — проверено: пропущенное поле даёт
`TS2741`, чужое значение enum — `TS2322`.

Чтобы посмотреть сайт на живом API, минуя снапшот:

```bash
CV_API_URL=http://localhost:3000/graphql npm run dev
```

## Откуда что берётся

| | Источник | Где править |
| --- | --- | --- |
| Имя, должность, био, опыт, навыки, проекты, сертификаты, ссылки | `lib/cv-snapshot.ts`, сгенерирован из GraphQL API | `prisma/seed/cv-data.ts` в репозитории API, затем `npm run cv:snapshot` |
| Заголовки секций, кнопки | Tolgee | Tolgee / `messages/*.json` |

Язык запрашивается у API аргументом `locale` — русская и английская версии
приходят из одной базы, а не из двух копий текста.

## Если правки в резюме не видны

Скорее всего не пересоздан снапшот — см. «Откуда берётся контент» выше.
Если пересоздан, а изменений нет, помогает `rm -rf .next`.

## Сборка и деплой

```bash
npm run build
```

`output: "export"` — на выходе статика в `out/`, страницы `/en` и `/ru`
генерируются при сборке из снапшота.

Сборка **не ходит в сеть за контентом**, поэтому Vercel собирает без доступа к
API. Проверено: с полностью погашенным API `npm run build` проходит, а в
`out/ru.html` лежит русский текст.
